计费网关落地实施方案

公私统一架构 · 私有云完全断网（离线 + 许可 + TPM）优先落地

配套文档：《计费网关设计文档》（讲清 why 与架构原理，附录 A–I）。本文档讲清 how to build：技术选型、数据模型、接口契约、部署拓扑、可观测性、测试与分阶段排期，目标是照着就能建。语言无关——只规定架构、接口、DDL、协议与流程。

5.2 私有云断网（嵌入式 KV + WAL）

私有云不用关系库。权威状态只有两类：许可文件 + WAL；嵌入式 KV 仅存可重建的派生缓存。

// 嵌入式 KV 的 buckets（可由 WAL 全量重建，损坏不丢账）
bucket "quota":       key=license_id        val={total, used, held}
bucket "idempotency": key=request_id        val={event_id, points, seq}
bucket "checkpoint":  key="last"            val={last_seq, last_hash, tpm_counter}
bucket "license":     key=license_id        val=已校验许可元信息

// WAL 段文件：append-only，按小时滚动，旧段 chattr +i
// 文件名：wal/YYYYMMDD/HH.seg     归档：archive/anchor-YYYYMMDD.json
// 每条记录 = CBOR(UsageRecordWire)，见 §6.3 的链式字段

// WAL 记录的物理布局（每条）
[ u32 len ][ CBOR payload ][ u32 crc32c ]
  payload = {
    seq, event_id, tenant_id, product_line, meter_code,
    raw_usage, smu_value, points, pricing_version, dimensions,
    occurred_at, wall_clock, tpm_counter,
    prev_hash(32B), this_hash(32B), kind  // kind: usage|heartbeat|phantom|freeze
  }

6.1 六段

①计量 → ②归一 → ③计价 → ④计费 → ⑤结算 → ⑥对账（详见设计文档附录 I）。本节给出落地实现要点。

6.2 ②归一与③计价：公私共享纯函数

// domain/meter/normalize  —— 原始单位 → SMU
func Normalize(meter Meter, raw float64, dims Dims) (smu float64) {
    switch meter.SmuUnit {
    case "kilotoken": return raw / 1000
    case "message":   return math.Ceil(rawLen(dims) / float64(segSize(dims)))
    case "second":    return raw
    case "image-unit":return imageWeight(dims)   // 分辨率×步数
    default:          return raw
    }
}

// domain/pricing/engine  —— SMU → 点数（公私逐字节相同）
func Calc(smu float64, dims Dims, plan PricingPlan) (points float64) {
    rule := plan.Match(meter, dims)              // 选中分档规则
    return math.Ceil(smu / rule.UnitSize * rule.PointsPerUnit * dims.Multiplier())
}

7.1 计费热路径（gRPC）

service BillingService {
  rpc Hold   (HoldRequest)   returns (HoldResponse);
  rpc Commit (CommitRequest) returns (CommitResponse);
  rpc Cancel (CancelRequest) returns (CancelResponse);

  string tenant_id = 1;
  string request_id = 2;          // 幂等键
  repeated Estimate estimates = 3;
  int32  ttl_sec = 4;

9.1 许可文件（自包含、单向）

{
  "license_id":"LIC-AIRGAP-2026-0001", "license_kind":"airgap_oneway",
  "tenant":"acme", "deployment_id":"DEP-7f2a", "hardware_fingerprint":"sha256:...",

  "quota":{ "total_points":10000000, "no_refund":true },

  • 签发：计费中心 HSM 持 Ed25519 私钥；客户先用 billing-cli env fingerprint 生成指纹经业务渠道报给厂商。

9.2 本地扣减正确性（设计文档附录 F 的落地）

机制落地实现
串行写入器单 actor goroutine/线程 + 请求队列；读走原子快照
扣减顺序TPM_NV_Increment → WAL.append → fsync → 内存生效 → 回包
不可篡改WAL 仅追加（chattr +a）+ Merkle 哈希链 + 每日 anchor TPM 签名
防回滚启动比对 last_record.tpm_counter vs TPM_NV_Read；落后即写 phantom，超前即冻结
时间证据每 60s 心跳消耗 0.01 点 + 持久化 max_seen_wall_clock
许可栈多张未过期许可按 valid_from 排队消耗，无缝续期

9.3 崩溃恢复算法

recover():
  1. 加载许可，验证签名 / 指纹 / seq 连续
  2. tpm_now = TPM_NV_Read(slot_usage)
  3. 从最近 anchor 顺序扫描 WAL，校验 prev/this_hash；尾部不完整记录按 CRC/CBOR 边界截断
  4. last = WAL 末条有效记录
  5. if last.tpm_counter > tpm_now:  → 冻结("tpm_rollback")   // 出现"未来"的扣费
  6. if last.tpm_counter < tpm_now - tol: 补 phantom_increment + 告警 // 幽灵增量
  7. 重建余额 available = Σlicense.total − Σcommitted − Σheartbeat
  8. 加载 idempotency 索引；启动 heartbeat
  9. 恢复期间对外 503，完成后 ready

9.4 无 TPM 的降级

降级策略无 TPM 的环境：优先 vTPM + Secure Boot；再不行用加密锁文件计数器（有 root 可绕过，仅开发/低安全环境），持续告警并进入"低信任模式"，且必须在合同中明确"客户承诺不回滚 VM"。生产涉密环境强制要求物理 TPM 2.0。

9.5 客户单方对账

billing-cli audit report --month YYYY-MM 生成含全部 Merkle Proof 的 PDF，用于客户内部成本分摊；厂商不参与（许可即收据）。

11. 持久化与耐久性（私有云关键路径）

  • WAL 段文件：O_APPEND | O_DSYNC 打开，每条记录 fsync 后才回包；fsync 失败即 panic（不可假装成功）。
  • Group commit：50ms 窗口或 64 条触发一次 fsync，配合 TPM 批量增量，目标 2K–5K commit/s、p99 < 100ms。
  • 批内崩溃只丢"未回包成功"的请求，业务侧用 request_id 重试，幂等保证不重复。
  • 嵌入式 KV 周期 checkpoint（每 100 条 / 30s）；损坏可由 WAL 全量回放重建。

17. 实施里程碑与排期

以"公私统一架构 + 断网优先"为主线，建议 6 个里程碑（人天为示意，按团队规模调整）：

里程碑交付物关键验收预估
M0 骨架proto + 领域模型 + 8 端口接口 + 契约测试框架 + CI 架构检查架构依赖检查通过；契约框架可跑2–3 周
M1 计价管道计量→归一→计价 纯函数 + Mock 适配器端到端同一用量在 mock 公私算出同点数2 周
M2 断网核心 P1License 解析/校验、WAL+Merkle、TPM 锚定、本地扣减、恢复故障注入（掉电/回滚/时钟）全过；audit verify 通过4–5 周
M3 断网闭环许可导入(QR/文本)、许可栈、心跳、单方对账报告、离线安装包客户可独立完成 导入→消费→对账→续期3 周
M4 公有云PgQuotaStore、Redis Lua、Kafka journal、充值、结算、多租户10K TPS；对账Σ一致3–4 周
M5 产线接入Go/Java/Python SDK + Sidecar + doctor + 沙箱新产线 ≤0.5 人日接入；公转私 0 改动3 周

关键路径：M0 → M1 → M2 → M3（断网先打通），M4/M5 可与 M3 部分并行（共用 M0–M1 成果）。

18. 风险与缓解

风险影响缓解
客户环境无 TPM断网防回滚失效vTPM/Secure Boot 降级 + 合同约束；售前明确硬件要求
领域层混入 IO 依赖单代码库失效CI 架构依赖检查强制拦截
多语言 SDK 行为漂移计费不一致proto 单源 + 共享契约集 + 薄 SDK
fsync 性能不达标断网 TPS 低group commit + TPM 批量；SSD 要求写入基线测试
许可人工分发出错装载失败/重放seq 严格递增 + 段校验位 + doctor 自检
对账长期不做差异累积难定位每次集成强制对账断言；生产每日批对账

19. 验收清单（Definition of Done）

统一架构

  • 领域层/用例层零 IO 依赖（CI 检查通过）
  • 同一用量在公有云与断网私有云算出完全相同的点数（自动化断言）
  • 8 个端口均有契约测试，公私实现全绿

私有云完全断网

  • 纯许可文件可经 QR/文本导入并激活
  • 掉电（kill -9）后重启不丢账、不重复扣（幂等）
  • VM 快照回滚被检测，进入 LEDGER_FROZEN
  • 时钟回拨 >60s 阻断扣费
  • audit verify 校验哈希链 + TPM + anchor 全通过
  • 客户可独立生成含 Merkle Proof 的对账报告
  • 许可栈无缝续期（旧许可耗尽自动切换）
  • 离线安装包零外网依赖完成部署

公有云

  • 多租户实时扣费，hold/commit 幂等
  • 单实例 ≥10K commit TPS、p99 <20ms
  • 每日批对账 计量Σ=计费Σ=结算Σ
